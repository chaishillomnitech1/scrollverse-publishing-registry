## Security hardening — per highway

*The lesson from Stripe: the VibeCanvas key ending JXAnel was deactivated after Stripe said it was publicly available. Never repeat that pattern. One leak must never take down every stream.*

### Rules that apply to every highway

1. **2FA everywhere** — Shopify, Printify, Gelato, PayPal, Cash App, Coinbase Commerce, Vydia, DistroKid, Gmail, Dropbox, GitHub. Authenticator app (not SMS) where offered. No shared 2FA.
2. **Separate API keys / secrets per stream** — one key per service, per purpose (e.g. Shopify-Printify key ≠ Shopify-Gelato key ≠ Stripe key). Never reuse a key across streams. Never commit a key to GitHub, a chat, a screenshot, or a shared doc.
3. **Separate wallets per stream** — one wallet per revenue stream / asset class. Business receipts never go to a personal wallet. Personal and business wallets are never mixed.
4. **No shared credentials** — no password reused across services. Password manager, unique password per service. No credentials in code, .env files in repos, or screenshots.
5. **Least privilege** — give each integration only the permissions it needs (e.g. Printify needs product/order access, not full store admin). Review connected apps quarterly.
6. **Key rotation plan** — rotate API keys every 90 days, or immediately after any staff/contractor change, any suspected exposure, or any service breach notice. Log rotation date + key last-four in a private key register (never the full key).
7. **If a key leaks — do this, in order:**
   1. Revoke / deactivate the leaked key immediately at the provider.
   2. Issue a fresh key for that stream only; update only that integration.
   3. Check the provider's logs for unauthorized use (orders, payouts, withdrawals) since the leak.
   4. If money moved, freeze the affected payout destination and contact the provider + bank.
   5. Record the incident (date, key, scope, what was done) in the security log. Do not reuse the leaked key's pattern.
   6. Review whether the same key/secret was used anywhere else — if yes, rotate those too.
8. **Payout locks** — payout bank / wallet changes require 2FA + email confirmation. Check payout destinations monthly; if a destination changed and Chais did not change it, treat it as a breach.
9. **Backups** — per-sale log, key register (last-four only), and security log backed up weekly, stored separately from the live store.
